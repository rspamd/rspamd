# Bundled Unicode / model data

These Lua tables are generated by `tools/gen.ts` from the impersonation-detector engine, so the
Lua port reproduces the engine exactly. Do not edit by hand; run `tools/gen.sh` to regenerate.

- **cpfold.lua** — per-code-point UTS #39 confusable skeleton, case-folded (the engine's
  `foldSkeleton`). This is the confusables table of UTS #39 section 4 with NFD applied, in the
  compact form the module loads.
- **cpcase.lua** — per-code-point case fold (`casefold`).
- **cpnorm.lua** — per-code-point `casefold(NFKC(c))`, used for tokenisation.
- **scripts.lua** — UTS #39 script ranges (copied from the engine's `scripts.json`), for the
  mixed-script check of section 5.
- **wordchars.lua** — `\p{L}\p{N}` ranges (token boundaries); **digits.lua** — `\p{Nd}` ranges.
- **weights.lua** — the logistic sender-score weights, copied from `scorer_weights.json`.

## One documented limitation

The skeleton / casefold / NFKC maps are applied **per code point** and concatenated. This matches
the engine's whole-string normalization for every input that occurs in mail (sender display names,
email addresses, domains, URL hosts) and is verified against the engine on its full benchmark
corpus (see `test/`). The single theoretical case it does not reproduce is cross-code-point
canonical reordering of two or more **stacked combining marks** that decompose across a code-point
boundary — a sequence that cannot appear in a DNS hostname and does not occur in the engine's
benchmark. If exact whole-string NFD becomes necessary, bundle a canonical decomposition + combining
class table and apply a canonical reorder after the per-code-point expansion.
